# DUBL2: одно статическое Frontend App в Timeweb

Сайт сохраняет Next.js App Router, TypeScript, CSS и существующий дизайн. FastAPI, базы данных, административная панель и S3 в текущей версии не используются. Полная версия сохранена в ветке [fullstack](https://github.com/Rasul05777/Dubl2/tree/fullstack). Для возврата к ней используйте отдельный checkout этой ветки; статический frontend в неё добавлять не нужно.

## Локальный запуск и сборка

Нужны Node.js 22 и npm. Python нужен только как необязательный простой HTTP-сервер для локальной проверки, не как backend сайта.

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:3000. Production-сборка:

```bash
npm run build
npm run typecheck
npm start
```

`npm start` раздаёт готовую папку `out` через локальный HTTP-сервер на порту 3000. Не открывайте index.html через file://. Для хостинга достаточно содержимого `frontend/out`: HTML, CSS, JS, изображения. Node.js runtime, backend, база данных и переменные API после сборки не нужны. `output: export`, `trailingSlash: true`, `images.unoptimized: true` уже настроены.

Сборка проверяет JSON через типизированные схемы, уникальность id/slug, связи категорий и наличие локальных изображений. Файлы более 1 МБ отклоняются. Суммы задаются строками с точкой и не более двух десятичных знаков, например `"280.00"`.

## Каталог

Редактируйте:

- `frontend/data/categories.json` — id, name, slug, sort_order, is_active.
- `frontend/data/products.json` — id, category_id, name, slug, description, price, weight, image_url, is_available, is_active, sort_order.
- `frontend/data/settings.json` — все настройки заведения и SEO.

Пример нового товара (добавьте объект в массив products.json, соблюдая запятые):

```json
{
  "id": 7,
  "category_id": 1,
  "name": "Латте",
  "slug": "latte",
  "description": "Эспрессо с нежным молоком",
  "price": "300.00",
  "weight": "300 мл",
  "image_url": "/images/products/latte.webp",
  "is_available": true,
  "is_active": true,
  "sort_order": 7
}
```

Используйте новый уникальный положительный id и уникальный slug латиницей. category_id должен существовать. Для смены цены измените только price. Меньший sort_order отображается раньше. `is_active: false` скрывает позицию; `is_available: false` оставляет карточку с подписью «Скоро вернётся» и запрещает добавление. Скрытая категория скрывает её товары и их страницы. Не переиспользуйте id удалённых товаров: он связывает сохранённую корзину с каталогом.

Данные доступны компонентам через `lib/catalog.ts` и `lib/settings.ts`, типы и схемы — `lib/models.ts`. В будущем источник можно заменить в этих слоях. Сейчас запросов за данными нет: JSON включается в сборку, основной контент уже присутствует в HTML.

Карточка получает статический адрес `/menu/latte/`, добавляется в sitemap при сборке. Удаление товара убирает его страницу. Старый адрес `/product/?slug=latte` перенаправляет в браузере на новую карточку. Главное меню выводит все товары без JavaScript, а фильтры и корзина работают после его включения.

## Фотографии

Положите оптимизированный WebP или AVIF в `frontend/public/images/products/` и укажите путь без `public`, например `/images/products/latte.avif`. Для обложки используйте `public/images/site/`; для отдельных фото категорий зарезервирована папка `public/images/categories/`. Сейчас карточки категорий используют фото первого товара категории, как в предыдущем интерфейсе.

Рекомендуемый размер товарного фото — 800–1200 px по длинной стороне, вес до 200–300 КБ. Не добавляйте большие оригиналы. Ограничение проверки — 1 МБ на изображение. Ширина изображений адаптивная; товары и категории используют lazy loading. Обложка первого экрана загружается сразу как CSS background. Обычные img поддерживают WebP/AVIF без серверного оптимизатора.

Текущая иллюстрация `cafe-selection.webp` — общий AI-кадр кофе, выпечки и десерта, а не реальные фотографии отдельных блюд. Замените её собственными снимками до публикации меню. Исходная обложка сохранена. Никакие фотографии не отправляются во внешнее хранилище.

## Контакты, WhatsApp и доставка

В settings.json заполните:

- `whatsapp`: международный номер, только 10–15 цифр, без `+`, пробелов и скобок.
- `contact_phone`: телефон для ссылки tel.
- `address`, `maps_url`: адрес и HTTPS-ссылка Яндекс Карт.
- `restaurant_name`, `logo_url`, `hero_image_url`, `hero_title`, `description`, `working_hours`.
- `delivery_enabled`, `pickup_enabled`.
- `minimum_order_amount`, `delivery_price`: суммы строками; `delivery_price: null` означает уточнение доставки сотрудником.
- `delivery_zone`: текст условий доставки.
- `social_links`: массив `{ "name": "Название", "url": "https://..." }`.
- `site_url`: фактический HTTPS-домен сайта, без завершающего слеша.
- `seo_title`, `seo_description`: общие SEO и Open Graph. У товаров отдельные метаданные.

Реальные контакты ранее не предоставлялись: они оставлены пустыми. Чужие или вымышленные номера не используются. Без WhatsApp сайт объясняет, что оформление пока не настроено. `site_url` содержит example.com и должен быть заменён перед публикацией для корректных sitemap и OG.

Корзина хранит только `{product_id, quantity}`. При загрузке и открытии проверяются id и доступность, недоступные товары удаляются с уведомлением. Старый формат корзины с копией товара автоматически преобразуется. Все цены берутся из текущего каталога, расчёт ведётся в копейках. При запрете localStorage корзина работает до обновления страницы и показывает уведомление.

Кнопка «Оформить заказ» валидирует форму и открывает `https://wa.me/…?text=…` в новом окне с текстом. Если popup блокируется, в форме остаются сообщение и ссылка «Перейти в WhatsApp». Имя, телефон, адрес и комментарий не сохраняются в localStorage и не отправляются на сервер сайта. Пользователь сам отправляет сообщение в WhatsApp. Любая сумма предварительная: сотрудник подтверждает актуальные цены, наличие и приём заказа. Онлайн-оплаты нет.

## Timeweb Cloud App Platform

Создайте **одно** Frontend App:

| Поле               | Значение         |
| ------------------ | ---------------- |
| Репозиторий        | Rasul05777/Dubl2 |
| Ветка              | main             |
| Тип                | Frontend         |
| Фреймворк          | Next.js          |
| SSR                | Выключен         |
| Рабочая директория | frontend         |
| Node.js            | 22               |
| Сборка             | npm run build    |
| Результат          | out              |

Backend App, PostgreSQL, S3 и переменные NEXT_PUBLIC_API_URL / DATABASE_URL не нужны. Удалите старые API-переменные из настроек сборки. Подключите домен и HTTPS средствами платформы, затем запишите этот домен в settings.site_url и пересоберите сайт. Если прежнее приложение было создано с SSR, создайте новое frontend-приложение без SSR — по документации платформы этот режим нельзя выключить в существующем SSR-приложении.

Включите автоматический deploy при push в main. Сначала убедитесь, что новый статический сайт опубликован и работает. Уже существующие платные облачные backend/БД/S3 не удаляются этим изменением исходников; их отключение и сохранение прежних данных выполняются отдельно в вашем аккаунте.

Официальные инструкции: [Next.js static export](https://nextjs.org/docs/app/guides/static-exports), [Timeweb Next.js](https://timeweb.cloud/docs/apps/deploying-frontend-apps/nextjs).

## Публикация изменений через GitHub

Через GitHub откройте нужный JSON → Edit → измените данные → Commit changes в main. Для изображения откройте `frontend/public/images/products` → Add file → Upload files, затем обновите image_url в JSON. Лучше объединить фото и товар в одном коммите через локальную рабочую копию или pull request, чтобы промежуточная сборка не ссылалась на отсутствующий файл.

Из локальной рабочей копии:

```bash
git add frontend/data frontend/public/images
git commit -m "Update menu"
git push origin main
```

Timeweb с включённым автодеплоем соберёт сайт заново. Новые цены попадут и в каталог, и в корзину. До завершения deploy пользователи видят предыдущую версию; открытая ранее вкладка может сохранять старый каталог до обновления. Поэтому сумма всегда предварительная.

## Проверки

```bash
cd frontend
npm ci
npm run build
npm run typecheck
npx playwright install chromium
npm run test:e2e -- --workers=1
```

Playwright сам запускает статическую раздачу out на 127.0.0.1:13000. Никакой backend запускать не нужно. Проверяются HTML без JavaScript, SEO, категории, изображения, количество/удаление/сохранение корзины, миграция старой корзины и текущие цены, формы доставки/самовывоза, сообщение WhatsApp и ограничения суммы, отсутствие API-запросов и ошибок браузера, прямые адреса и отсутствие /admin. Mobile-профиль использует Chromium, Safari отдельно не проверяется.
